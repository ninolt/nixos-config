# ❄️ NixOS Configuration

My personal NixOS configuration for laptop reproducibility and declarative system management.

## What is NixOS?

[NixOS](https://nixos.org/) is a Linux distribution built on top of the [Nix package manager](https://nixos.org/manual/nix/stable/). It takes a **declarative** approach to system configuration:

- **Declarative**: Your entire system—packages, settings, services, dotfiles—is defined in configuration files (primarily `configuration.nix`)
- **Reproducible**: Given the same configuration files, you'll get identical systems every time
- **Atomic**: System updates are atomic; you can roll back to previous configurations instantly
- **Functional**: Based on functional programming principles, making configurations composable and maintainable

### Why Reproducibility Matters

Traditional Linux distributions use imperative package managers (apt, yum, pacman) where you run commands to install/update packages. Over time, this leads to:
- **Configuration drift**: Systems diverge from each other despite starting the same
- **Dependency hell**: Unclear what exactly your system depends on
- **Difficult recovery**: Hard to reproduce the exact state that was working

NixOS solves this by:
- Storing all configuration in **version-controlled files**
- Using **content-addressable packages**: Dependencies are tracked deterministically
- Enabling **quick rollbacks**: Revert to any previous configuration instantly
- Providing **easy system reproduction**: Deploy the same setup on another machine by cloning the config

## Why I Use NixOS

### 1. **Configuration as Code**
Everything about my system is defined in Git-tracked `.nix` files. No manual `sudo apt-get install` commands that get lost. My entire setup is reproducible and auditable.

### 2. **Dotfile Management**
Using Home Manager, I declaratively manage:
- Shell configurations (zsh)
- Editor settings (Neovim)
- Application configs
- Development environments

All synchronized across systems automatically.

### 3. **Development Environments**
With `flake.nix` and Nix development shells, I can:
- Create per-project isolated environments
- Pin exact versions of tools and dependencies
- Eliminate "works on my machine" problems
- Share reproducible dev setups with colleagues

### 4. **System Rollback**
If an update breaks something, I can roll back to the previous generation with one command. No need for recovery media or backups.

### 5. **Declarative Window Manager & Services**
My entire desktop environment (including Sway window manager) is configured declaratively, making it portable and version-controlled.

### 6. **Garbage Collection & Cleanliness**
Nix tracks exactly what's used. Unused packages are easily removed, keeping the system clean and optimized.

## Configuration Structure

- **`flake.nix`**: Nix Flakes entry point; defines inputs (nixpkgs, home-manager, etc.) and outputs
- **`configuration.nix`**: Core system configuration (kernel, bootloader, services)
- **`system.nix`**: Additional system-level configurations
- **`hardware-configuration.nix`**: Hardware-specific settings (generated by NixOS)
- **`home/`**: Home Manager configurations for user packages and dotfiles
- **`dev/`**: Development environment configurations
- **`secrets/`**: Encrypted secrets managed with agenix

## Key Dependencies

- **[Home Manager](https://github.com/nix-community/home-manager)**: Declarative user environment management
- **[agenix](https://github.com/ryantm/agenix)**: Secrets management
- **[swayfx](https://github.com/WillPower3309/swayfx)**: Enhanced Sway window manager
